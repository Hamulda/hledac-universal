- SprintLifecyclePipeline orchestrates 8 acquisition lanes with per-lane pre/post lifecycle hooks
- Lifecycle states follow a 3-tier progression: pending → acquiring → acquired → releasing → released
- Implements lifecycle-aware module loading where modules register hooks for state transitions
- Blocks execution of next sprint until current sprint reaches released state
- WAL (Write-Ahead Log) ensures durability; shadow store serves as scratch space
- Bounded inference mechanism prevents runaway loops during acquisition
- Key implementation files: runtime/sprint_scheduler.py, runtime/sprint_entrypoint.py, core/__main__.py
